SCM and Version Control

Module 02 · Beginner level · About 15 minutes

1. What is Source Code Management (SCM)?

Source Code Management is the process of tracking, organising and managing changes made to source code. It helps developers work together and maintain a history of their project changes.

2. What is Version Control?

Version control is a system that records changes made to files over time. Developers can compare different versions, view previous changes and restore earlier work when needed.

3. Types of Version Control Systems

Local VCS

Stores file versions on one local computer.

Centralized VCS

Uses a central server to store project history.

Distributed VCS

Each developer can have a complete local repository.

4. What is Git?

Git is a distributed version control system. It allows developers to track changes, create branches and collaborate on projects.

5. Important Git Concepts

  • Repository: Stores project files and history.
  • Working Directory: Where developers edit files.
  • Staging Area: Holds changes selected for the next commit.
  • Commit: A recorded snapshot of changes.
  • Branch: An independent line of development.
  • Remote: A repository hosted somewhere else, such as GitHub.

6. Basic Git Commands

git init

Creates a new local Git repository.

git add

Stages changes for a commit.

git commit

Saves a snapshot in repository history.

git status

Shows the current state of files.

git push

Uploads local commits to a remote repository.

git pull

Fetches and integrates remote changes.

7. Clone, Push and Pull

  • Clone: Copies a remote repository to your computer.
  • Push: Sends your committed changes to the remote repository.
  • Pull: Fetches and integrates changes from the remote repository.
