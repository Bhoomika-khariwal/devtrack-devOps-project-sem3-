1. Introduction to DevOps

DevOps combines software Development (Dev) and IT Operations (Ops). It is a combination of culture, practices, processes and tools that helps organizations develop and deliver software faster and more reliably.

What is Development?

Development involves planning, designing, writing, testing and improving application code. Developers create new features and fix bugs.

What is Operations?

Operations involves deploying, running, monitoring, maintaining and supporting applications and their infrastructure.

Development + Operations → DevOps

Main Goal of DevOps

  • Improve collaboration between teams.
  • Deliver software faster and more reliably.
  • Automate repetitive development tasks.
  • Detect errors early through continuous testing.
  • Improve software quality and stability.
Example: A shopping website needs a new payment feature. Developers write the feature, testers verify it, and operations deploys and monitors it. DevOps helps these activities work together through a continuous automated workflow.

2. History and Need for DevOps

Earlier, software development and operations teams often worked separately. Developers focused on creating new features, while operations teams focused on system stability.

This separation sometimes caused slow releases, communication problems, deployment failures and difficulties in fixing production issues.

How DevOps Evolved

Traditional Development → Agile → DevOps

Agile improved software development through short iterations and frequent feedback. DevOps extends collaboration into testing, delivery, deployment, operations and monitoring.

Why Do We Need DevOps?

  • To reduce delays in software delivery.
  • To improve communication between teams.
  • To automate building, testing and deployment.
  • To detect bugs earlier.
  • To reduce repetitive manual work.
  • To support continuous feedback and improvement.
Real-world example

Imagine a college portal where developers add an online fee-payment feature. Without coordinated processes, deployment might be delayed. With DevOps, the team can use version control, automated tests and a deployment pipeline to deliver the feature more reliably.

3. Traditional Development vs DevOps

Parameter Traditional Approach DevOps
Teamwork Teams often work separately Shared collaboration
Testing May happen late Integrated throughout development
Deployment Often manual Frequently automated
Feedback May be delayed Continuous feedback encouraged
Release Frequency Often less frequent Supports frequent releases
Responsibility Often divided by department Shared across the delivery lifecycle

Agile vs DevOps

Agile is a software development approach focused on iterative development, customer feedback and adapting to changing requirements.

DevOps complements Agile by connecting development with testing, delivery, operations and monitoring.

Agile and DevOps are not competitors. A software team can use both together.

4. Core Principles of DevOps

Collaboration

Developers, testers and operations teams work toward shared goals.

Automation

Repetitive tasks such as builds, tests and deployments are automated.

Continuous Improvement

Teams learn from monitoring, feedback and previous failures.

Shared Responsibility

Teams cooperate to maintain software quality and reliability.

CALMS Framework

CALMS describes five important aspects of DevOps culture and practices.

C — Culture

Encourage communication, teamwork, trust and shared responsibility.

A — Automation

Automate repetitive tasks to improve consistency and reduce manual errors.

L — Lean

Reduce unnecessary work, delays and waste in the software delivery process.

M — Measurement

Measure deployment performance, reliability, errors and recovery time.

S — Sharing

Share knowledge, feedback, tools and lessons learned across teams.

5. DevOps Lifecycle

The DevOps lifecycle is a continuous process used to develop, test, release, operate and improve software.

Plan→ Code→ Build→ Test→ Release→ Deploy→ Operate→ Monitor↻

Click each stage to understand its purpose.

1. Plan

Gather requirements, identify features, prioritize tasks and plan development. Tools include Jira and GitHub Issues.

2. Code

Developers write and maintain source code. Git tracks changes and supports collaboration.

3. Build

Source code and dependencies are prepared to create executable software or deployable artifacts.

4. Test

Automated tests verify functionality and help identify bugs before release.

5. Release

A tested software version is packaged, versioned and prepared for delivery.

6. Deploy

The application is installed or updated in a target environment such as staging or production.

7. Operate

Teams maintain the running application, infrastructure, availability and services.

8. Monitor

Logs, metrics and alerts help detect errors and performance problems. Feedback is used for future improvements.

Example Git Workflow

git init
git add .
git commit -m "Initial commit"
git branch feature-login
git switch feature-login

This example initializes a repository, commits changes, creates a feature branch, switches to it and pushes it to a configured remote named origin.

7. Introduction to CI/CD

Continuous Integration (CI)

Continuous Integration means developers frequently integrate code changes into a shared repository. Automated builds and tests help detect problems early.

Continuous Delivery

Continuous Delivery means software is automatically built, tested and prepared for release. Production deployment may still require manual approval.

Continuous Deployment

Continuous Deployment automatically releases changes to production after all required automated checks pass.

Push Code→ Build→ Test→ Release→ Deploy

Benefits of CI/CD

  • Early detection of integration errors.
  • Faster feedback on code changes.
  • Repeatable builds and tests.
  • More consistent software releases.
  • Reduced repetitive manual work.

8. Testing in DevOps

Software testing verifies whether an application behaves as expected. Automated testing allows checks to run repeatedly whenever code changes.

Unit Testing

Tests individual functions or components.

Integration Testing

Checks whether different components work together.

System Testing

Tests the complete integrated application.

Regression Testing

Checks that new changes have not broken existing functionality.

Example: Python Unit Test

def add(a, b):
    return a + b

def test_add():
    assert add(2, 3) == 5

The test checks whether the add() function returns the expected result. A tool such as pytest can run the test and report whether it passes or fails.

Why Automate Testing?

  • Tests can run after every code change.
  • Problems can be identified earlier.
  • Teams receive faster feedback.
  • Repetitive manual testing is reduced.

9. Deployment and Monitoring

Deployment is the process of making an application version available in its target environment.

Deployment Strategies

Rolling Deployment

Application instances are updated gradually rather than all at once. This can help maintain availability during deployment.

Blue-Green Deployment

Two environments are maintained. The new version is tested in one environment before traffic is switched to it.

Canary Deployment

A new version is released to a small group of users first. Its performance is checked before expanding the rollout.

What is Rollback?

Rollback means returning to an earlier working version when a new release causes problems.

Why is Monitoring Important?

  • Detect application errors.
  • Track response times and performance.
  • Monitor resource usage and availability.
  • Identify problems after deployment.
  • Support troubleshooting and improvement.
Deploy→ Monitor→ Feedback→ Improve

10. Real-world DevOps Example

Imagine a college team developing a Student Attendance Management System.

How DevOps Helps This Project

  1. Plan: The team decides to add an attendance report feature.
  2. Code: A developer writes code on a feature branch.
  3. Version Control: The developer pushes the branch to GitHub.
  4. Collaboration: A pull request is created for code review.
  5. Testing: GitHub Actions runs automated tests.
  6. Integration: The team reviews and merges the changes.
  7. Deployment: A deployment workflow releases the updated application.
  8. Monitoring: The team checks logs and metrics for any new problems.
This example connects planning, development, collaboration, testing, deployment and monitoring into one continuous workflow.
