1. Introduction to Git and GitHub

Git is a distributed version control system. It records changes to project files and helps developers work on the same project.

GitHub is an online platform for hosting Git repositories and collaborating through pull requests, issues, code reviews and automation.

Write Code→ Git Tracks Changes→ GitHub Hosts Repository

Why Git?

  • Keep a history of changes.
  • Work on separate features using branches.
  • Compare different versions of files.
  • Collaborate without sharing files manually.
  • Recover earlier working versions.
Example: A college team creates a website. One member builds the login page and another builds the dashboard. Git helps them track and combine their work.
Is Git the same as GitHub?

No. Git is the version control software. GitHub is a hosting and collaboration service built around Git repositories. You can use Git locally without GitHub.

2. Installing and Configuring Git

On Windows, install Git for Windows from the official Git website. Git Bash provides a terminal where you can execute Git commands.

Check Installation

git --version

Displays the installed Git version.

Set Your Identity

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Replace these placeholders with your own name and email. Git uses this information to identify the author of new commits.

View Configuration

git config --global --list
What does --global mean?

It sets the configuration for your Windows user account. A repository can override these settings using local configuration.

Git Bash is a terminal, Git is the version control system, and GitHub is a web platform. These are three different things.

3. Git Architecture and Three Areas

Understanding Git's three main areas makes commands such as add, commit and restore much easier.

Working Directorygit add → Staging Areagit commit → Local Repository

Working Directory

The files you currently create or edit in your project folder.

Staging Area

A preparation area where you choose changes for the next commit.

Local Repository

The Git database that stores commits and repository history.

Example

git status
git add index.html
git commit -m "Create homepage"
What is the .git folder?

The hidden .git directory stores Git's internal repository data, including objects, references and configuration. Do not manually edit its contents during normal development.

4. Creating a Git Repository

A repository is a project tracked by Git. You can initialize a new repository or clone an existing one.

Initialize a New Project

mkdir git-practice
cd git-practice
git init
git status

git init creates the Git repository. git status displays the current branch and file state.

Clone an Existing Project

git clone https://github.com/OWNER/REPOSITORY.git

Replace OWNER and REPOSITORY with a real repository URL. Cloning downloads the repository and its history.

Useful Files

  • README.md explains the project.
  • .gitignore lists intentionally untracked files.
  • .github/workflows/ can store GitHub Actions workflows.
Practice repository commands in a separate sample folder, not inside your active DevTrack repository.

5. Staging, Commits and History

A commit records a snapshot of staged changes. Good commit messages explain what changed.

Modify File→ Stage Changes→ Commit→ Inspect History

Common Commands

git status
git add index.html
git diff
git diff --staged
git commit -m "Add homepage"
git log --oneline
git show HEAD
CommandPurpose
git statusCheck tracked, modified and staged files.
git addStage selected changes.
git diffView unstaged changes.
git diff --stagedView staged changes.
git commitRecord staged changes.
git logInspect commit history.
Does git add upload files to GitHub?

No. git add only updates the local staging area. git commit saves locally. git push transfers commits to a remote repository.

6. Branching and Switching

A branch is a movable reference to a line of commits. Teams commonly use branches to develop features separately.

main→ feature-login→ Review→ Merge

Create a Feature Branch

git switch -c feature-login
git branch
git status

Switch to an Existing Branch

git switch main

View All Branches

git branch -a
git switch -c vs git checkout -b

Both can create and switch to a new branch. git switch was introduced to provide a clearer command for branch switching.

A feature branch allows you to work without immediately changing the main branch. Branches are not complete duplicate project folders.

7. Merging and Merge Conflicts

Merging integrates changes from one branch into another.

Basic Merge

git switch main
git merge feature-login

Types of Merge

Fast-forward

Git advances the branch pointer when no divergent commits need combining.

Three-way Merge

Git combines divergent histories using their common ancestor.

Squash Merge

Combines changes into a single new commit rather than preserving every feature commit on the target branch.

What Is a Merge Conflict?

A conflict occurs when Git cannot automatically decide how to combine incompatible changes.

Conflict Detected→ Review Changes→ Edit File→ Stage Resolution
How do I complete a conflicted merge?

Open the conflicting file, resolve the differences, test the result, stage the resolved file with git add, and complete the merge with git commit or git merge --continue as appropriate.

Never resolve conflicts by blindly deleting another contributor's changes. Review both versions first.

8. Remote Repositories: Clone, Fetch, Pull and Push

A remote is another repository location. Teams often use GitHub as their shared remote.

Local Repositorygit push → GitHub Remote

Useful Commands

git remote -v
git fetch origin
git pull origin main
git push -u origin feature-login
CommandWhat It Does
git cloneCreates a local repository copy.
git fetchDownloads remote references and objects without automatically integrating them into your current branch.
git pullFetches and integrates remote changes.
git pushUploads local commits to a remote.
What are origin and upstream?

origin is the conventional name for a cloned repository's remote. upstream is often used for the original project when working with a fork. These are configurable names, not special Git commands.

Before pushing shared work, check your current branch and repository status. Do not use force push unless you understand the consequences.

9. GitHub Collaboration and Pull Requests

GitHub provides tools for reviewing and integrating Git changes.

Typical Collaboration Workflow

Create Branch→ Commit→ Push→ Pull Request→ Review and Merge

Important GitHub Features

  • Pull Request: Propose changes for review and integration.
  • Issues: Track tasks, bugs and suggestions.
  • Code Review: Discuss and approve changes.
  • Actions: Automate builds, tests and other workflows.
  • Branch Protection: Enforce rules before merging.
Pull request vs git pull

A pull request is a collaboration feature on platforms such as GitHub. git pull is a Git command that fetches and integrates changes from a remote.

Fork vs clone

A fork is a separate repository created under another account or namespace on a hosting platform. A clone is a local copy of a Git repository.

10. Undoing Changes: Restore, Reset, Revert and Stash

Git provides different tools for different recovery situations. Choosing the correct command helps protect your work.

CommandPurpose
git restoreRestore file content from a selected source.
git restore --stagedRemove changes from the staging area.
git resetMove HEAD and optionally update the index or working tree.
git revertCreate a new commit that reverses an earlier commit.
git stashTemporarily save certain uncommitted changes.

Safe Inspection Commands

git status
git log --oneline
git diff
git stash list

Unstage a File

git restore --staged index.html

Revert a Commit

git revert COMMIT_HASH

Replace COMMIT_HASH with the commit you want to reverse. Revert is commonly preferred for undoing changes already shared with collaborators.

Why is git reset --hard risky?

It can discard uncommitted changes in tracked files. Avoid using it on important work without understanding exactly what will be lost.

11. Advanced Git Concepts

Git Rebase

Rebase replays commits onto a different base, often creating a more linear history. Because it rewrites commit identities, coordinate carefully before rebasing shared branches.

Cherry-pick

Cherry-pick applies the change introduced by a selected commit onto your current branch, creating a new commit.

git cherry-pick COMMIT_HASH
Git Tags

Tags identify specific commits, often for releases.

git tag v1.0.0
git tag --list
Git Hooks

Hooks are scripts that Git can run during certain events, such as before committing. They can support local validation and automation.

Submodules and Subtrees

Submodules reference another repository at a specific commit. Subtrees allow another project's files to be incorporated and managed within a repository.

Visualize Branch History

git log --oneline --graph --all --decorate

12. GitHub vs GitLab

Both platforms host Git repositories and provide collaboration features. Their interfaces and built-in tooling differ.

FeatureGitHubGitLab
Code HostingYesYes
Review FeaturePull RequestsMerge Requests
CI/CDGitHub ActionsGitLab CI/CD
Issue TrackingYesYes
Git CommandsStandard GitStandard Git
Commands such as git add, git commit, git branch and git push work with both GitHub and GitLab repositories. The remote repository URL is what changes.
